# Web 请求的基本流程

Web 请求从用户输入 URL 到页面展示，经历了多个重要步骤：

## 1. URL 解析

- 浏览器解析用户输入的 URL
- 验证格式并确定协议类型(HTTP/HTTPS)

## 2. DNS 解析

- 将域名转换为服务器 IP 地址
- 查询顺序：浏览器缓存 → 系统缓存 → 路由器缓存 → ISP DNS 服务器 → 根域名服务器

## 3. 建立 TCP 连接

- 通过 TCP 三次握手建立连接：
  - 客户端发送 SYN 包
  - 服务器回应 SYN-ACK
  - 客户端确认 ACK

## 4. HTTPS 安全连接(如适用)

- 进行 TLS/SSL 握手
- 交换加密密钥，建立安全通道

## 5. 发送 HTTP 请求

- 构建 HTTP 请求报文(请求行、请求头、请求体)
- 通过已建立的连接发送到服务器

## 6. 服务器处理

- Web 服务器接收请求
- 应用服务器处理业务逻辑
- 可能查询数据库或调用其他服务

## 7. 返回 HTTP 响应

- 服务器构建响应报文
- 包含状态码、响应头和响应内容

## 8. 浏览器渲染

- 解析 HTML 构建 DOM 树
- 解析 CSS 构建 CSSOM 树
- 生成渲染树并绘制页面
- 加载额外资源(JavaScript、图片等)

## 9. 连接关闭

- 根据 Connection 头部决定是否保持连接
- 如需关闭，执行 TCP 四次挥手

这个流程在现代 Web 应用中可能更加复杂，涉及缓存机制、CDN 加速、并行请求等多种优化技术。

# TCP/IP 协议与 HTTP 协议解析

## TCP/IP 协议

TCP/IP (传输控制协议/网际协议) 是互联网通信的基础协议套件，它实际上是一组协议的集合，而非单一协议。TCP/IP 协议栈通常分为四层架构：

- **应用层**：提供应用程序间通信(如 HTTP、FTP、SMTP 等)
- **传输层**：负责端到端数据传输，主要包括 TCP(可靠传输)和 UDP(快速传输)
- **网络层**：负责数据包路由和寻址，核心是 IP 协议
- **网络接口层**：处理物理网络连接细节

TCP 协议确保数据可靠传输，提供流量控制、拥塞控制和错误恢复；IP 协议负责将数据包从源地址路由到目标地址。

## HTTP 协议

HTTP (超文本传输协议) 是应用层协议，建立在 TCP/IP 基础之上，专门用于 Web 浏览器与服务器之间的通信。主要特点：

- 采用请求-响应模型
- 无状态协议(每次请求独立，服务器不保留上下文)
- 标准方法包括 GET、POST、PUT、DELETE 等
- 默认使用 TCP 的 80 端口
- 定义了资源定位(URL)、消息格式和状态码等规范

HTTP 是万维网(WWW)的数据通信基础，而 HTTPS 是其安全版本，通过 SSL/TLS 加密保障数据传输安全(使用 443 端口)。

简言之，TCP/IP 是互联网通信的基础设施，而 HTTP 是运行在其上的一种具体应用协议。

# 网络请求与响应的核心组件

## URL (统一资源定位符)

- 用于指定互联网上资源的地址
- 基本格式：`协议://域名或IP地址[:端口]/路径?查询参数#片段标识符`
- 例如：`https://www.example.com/users?id=123`

## IP 地址

- 互联网协议地址，唯一标识网络上的设备
- IPv4 格式：`192.168.1.1`
- IPv6 格式：`2001:0db8:85a3:0000:0000:8a2e:0370:7334`

## 请求头 (Request Headers)

- HTTP 请求中的元数据，提供额外信息
- 常见请求头：
  - `User-Agent`: 客户端信息(浏览器/设备)
  - `Accept`: 客户端能处理的内容类型
  - `Content-Type`: 请求体的数据格式
  - `Authorization`: 身份验证凭证
  - `Cookie`: 客户端存储的 cookie 值

## 响应头 (Response Headers)

- HTTP 响应中的元数据，提供服务器响应信息
- 常见响应头：
  - `Content-Type`: 响应体的 MIME 类型
  - `Content-Length`: 响应内容大小
  - `Set-Cookie`: 服务器要求设置的 cookie
  - `Cache-Control`: 缓存策略
  - `Location`: 重定向目标 URL

## 负载 (Payload)

- 也称为请求体/响应体，包含实际传输的数据
- 常见格式：JSON、XML、表单数据、文件等
- GET 请求通常无负载，POST/PUT 请求通常包含负载

## 状态码 (Status Code)

- 表示请求处理结果的三位数代码，分为五类：
  - **1xx 信息**：请求已被接收，继续处理 (100 Continue)
  - **2xx 成功**：请求成功完成 (200 OK, 201 Created)
  - **3xx 重定向**：需要进一步操作 (301 Moved Permanently, 302 Found)
  - **4xx 客户端错误**：请求有误 (400 Bad Request, 404 Not Found)
  - **5xx 服务器错误**：服务器处理失败 (500 Internal Server Error, 503 Service Unavailable)
